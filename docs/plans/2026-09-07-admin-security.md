# 管理安全首个子切片：初始化与本人账号安全

属于[完整管理台计划](2026-09-07-admin-complete.md)切片 1 的首个可独立验收子切片（1a），不是整个安全阶段完成。先保留现有 `admin/user` 角色，所有者迁移、角色矩阵、邀请、登录限流和全局路由仍在切片 1/2 后续队列，不在没有迁移依据时自动提升现有账号。

## 已确定的实现边界

- 运行时不再 upsert 覆盖账号。Postgres 首次初始化在事务中锁定账号表，以持久标记拒绝重复创建；有管理员的旧实例仅记录初始化完成，不改其凭据/角色。
- 无管理员的新实例须由服务器环境明确提供 `PROMPTARK_ADMIN_EMAIL/PASSWORD`；只有显式 `PROMPTARK_ALLOW_DEV_USER=1` 才允许默认开发凭据，且普通开发账号只插入不更新。撞到已有普通用户同名邮箱时拒绝初始化，不提权。
- 管理端新增本人「账号安全」：读取口令是否设置、当前 Access 数量；验证当前密码后修改密码；明确确认后退出本人的所有设备。成功后清空本机登录并回到登录页。无本地密码的 OAuth 账号暂不提供设置密码捷径。
- 新密码 12–128 个 Unicode 字符、最多 512 UTF-8 字节，不 trim；不能与旧密码相同。错误当前密码、非法输入或非管理员不写数据。
- 口令更新、全量 Access/Refresh 撤销及本次成功审计必须同一事务；当前请求的令牌和角色在取得账号锁后重新校验。登录验证/签发、Refresh 轮换/签发也用同一账号锁和事务，阻止并发旧凭据复活会话。
- Postgres 是授权来源，Redis 旧副本不能使撤销令牌有效。新增安全接口只支持持久化运行态，无数据库时明确返回 503，不模拟成功。
- 成功审计仅存事件 ID、账号、动作和时间，不存秘密。失败操作不产生成功记录；全量失败审计和日志查询页在后续切片处理。

## 迁移与回退

仅增加初始化标记和安全审计表，不删除现有列或数据。回退应用前应保留数据库及 OAuth 密钥备份；旧二进制含覆盖密码的启动逻辑，不能直接启动旧版本当作安全回退。遇到初始化失败先检查账号与服务器环境，不通过删库/改角色绕过。新实例未初始化时允许启动失败给出明确服务器配置提示，不开匿名网页初始化接口。
