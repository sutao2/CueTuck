# 广场与详情布局优化

状态：已实施验收，未部署、未发版。

## 方案

- 本轮调整桌面工作台的两个广场。统一页头的字号、留白、搜索高度和按钮密度，社区/GitHub 各自入口继续保持边界。官网部署独立执行。
- 提示词详情正文在 DOM 中先于参考图。内容区足够宽时采用正文＋参考图双栏，窄时单列正文优先，无图片时正文占满。图片仍使用原大图查看器，保留作者、来源、许可、附件及合集使用入口。
- 详情动作栏在当前滚动面内粘滞，避免长正文时找不到使用；不重复增加第二组按钮。
- 小于 900px 的工作台默认收起侧栏，允许显式展开；宽窗口沿用已保存布局。窄屏选择只留于当前运行，不覆盖宽屏偏好。筛选允许换行、控件不挤压或溢出。

## 验收场景

- Given 图文提示词 When 查看详情 Then 正文先于参考图，使用采用当前语言，作者/附件/来源仍可访问。
- Given 长正文 When 滚动到底部 Then 主操作保持可见；点击图片打开原查看器，关闭后继续阅读。
- Given 无图或合集 When 查看详情 Then 无空侧列且成员使用按钮正常。
- Given 1440px / 820px / 600px 与浅深色 When 查看两个广场及详情 Then 标题、筛选、按钮不横向溢出；双栏在可用宽度不足时转单栏。
- Given 已保存宽屏侧栏状态 When 缩窄、展开侧栏、再放宽 Then 宽屏状态和宽度恢复，不被窄屏动作覆盖。

组件回归覆盖内容/动作和布局偏好，Playwright 在隔离本机预览进行多尺寸与滚动可视验收。全量前端、构建、docs-check 通过后提交。未进行部署、打包发版或真实账号操作。
