## 1. 产品目标

让用户在 CueTuck 看清本机有哪些 Skill、分别供哪些智能体使用，并从公开来源安装到指定客户端或项目。提示词用于输入、变量填写与快速调用；Skill 是包含说明、脚本和资料的文件包。两者有共同的浏览体验，但保留不同的数据模型和操作。

第一版的价值是发现、看懂、安装、维护。不是管理智能体的模型供应商、账号或聊天会话，也不承诺安装文件后所有专有工具都能跨客户端工作。

## 2. 同类参考与取舍

以下是对官方项目资料的参考，不代表已安装测试这些软件，也不以项目自报支持数量作为兼容性证明。查阅日期 2026-09-13。

| 参考 | 已公开的做法 | 本方案借鉴 |
|---|---|---|
| [Skills Manager](https://github.com/xingkongliang/skills-manager) | 统一资源库、全局/项目工作区、按智能体分配，展示外部安装内容 | 区分 Skill 与它在各位置的安装记录；本机已有内容直接可见 |
| [SkillDeck](https://github.com/crossoverJie/SkillDeck) | 列表与详情、公开目录浏览、按智能体分配 | 以 Skill 为浏览主体，在详情里展示安装位置 |
| [CC Switch](https://github.com/farion1231/cc-switch) | Prompts、Skills、MCP 分模块；GitHub/ZIP 安装 | 提示词与 Skills 分组，不扩张到供应商管理 |
| [Vercel Skills CLI](https://github.com/vercel-labs/skills) | 仓库安装、选择 Skills/智能体/作用范围，支持共享链接与独立复制 | 安装流程采用相同的用户决策顺序 |
| [skills.sh](https://skills.sh/) | 在线 Skill 发现目录 | 参考搜索和来源展示；接入前需核实可用接口与使用条件 |

推荐先以原生文件操作完成有界的目录包安装，不要求用户安装 Node.js 或 Git。不会从网页提取任意命令自动运行。后续若接入通用 CLI，也应固定版本并保留可解释的安装计划，不运行无版本限制的安装命令。

## 3. 导航和页面布局

侧栏使用两个分组标题，每组下有对称的两个入口。不是四个无分组按钮，也不再使用「Skills → 本机/广场/智能体」三级入口。

```text
提示词
  提示词广场
  本地提示词

Skills
  Skill 广场
  本机 Skills

[当前内容的分类区域]

设置 / 账号
```

提示词页保留原分类树。切到 Skills 后隐藏提示词分类，不让无关分类占用侧栏；Skill 的智能体、范围和来源筛选放在内容页。智能体目录管理从本机页的「管理目录」进入，不单独占主侧栏。

### 本机 Skills

```text
本机 Skills                          添加来源  管理目录  刷新
已发现 28 个 Skill · 43 处安装（示例）

[搜索名称、描述] [全部智能体] [全局 / 项目] [全部状态]

Skill              安装到                 来源       状态
代码审查           Codex · Cursor        GitHub     可检查更新
写作助手           Claude Code           本地       外部管理
文档处理           Codex                 插件       只读
```

数字仅为布局示例。默认用列表，优先显示名称、描述、智能体标记、作用范围、来源和状态；多位置不展开成大量重复卡片。点击 Skill 进入详情页面，返回时保留筛选与滚动位置。

同名不是同一个 Skill：仅当规范化物理路径相同，或有明确的同一仓库/目录来源时聚合。内容不同的安装保留版本差异；没有来源证据的同名内容分开显示。复制未修改的已管理内容时保留已验证的仓库来源；已修改的副本按本地来源复制，避免将修改内容误标为上游版本。统计明确区分逻辑 Skill 数与安装位置数。

### Skill 详情

- 名称、描述、来源仓库与目录、版本/提交、许可信息（未知则明确显示未知）。
- 正文预览与文件清单；不执行脚本，不把正文中的指令当作应用操作。
- 安装位置列表：智能体、全局/项目、实际路径、管理方式、当前版本。
- 操作：安装到其他位置、打开文件夹、检查更新、从指定位置移除。
- 插件或外部链接标注由原工具管理；依赖专有 MCP、脚本运行时的内容显示其声明，安装成功仅表示文件就绪。

### Skill 广场

首版以可追溯的公开 GitHub 仓库为来源，不假装已有全网目录和排行榜。

- 顶部搜索、来源切换、添加仓库地址。
- 内置来源使用 `desktop/src/data/skill-sources.json` 中的公开仓库目录，覆盖文档、开发、AI、云服务、安全、营销、科研和视频制作。新增来源须核查真实目录、许可和可访问性；来源选择器显示用途与仓库名，可搜索，保留用户自定义来源并按仓库大小写去重。数量根据实际加载的目录展示，不把各仓库条目之和宣称为去重 Skill 数。
- 支持 owner/repo 和 GitHub 仓库/Skill 目录链接；分支名含斜线时应由仓库元数据解析，不能靠截取固定 URL 段猜测。
- 显示来源、简介、安装状态；没有安装量或推荐算法时不显示伪造的热度。
- 缺省搜索仅针对已加载的当前来源名称、路径及已读取简介（简介按页并发读取），明确搜索范围；跨来源统一搜索属于后续聚合能力。
- 点击进入详情，先查看内容和文件，再安装；安装固定在已经预览的版本。
- 网络失败、API 限流、列表被截断均明确反馈，支持重试，不显示成「没有 Skill」。

## 4. 安装与导入流程

```text
广场选中 Skill / 粘贴仓库链接 / 选择本地文件夹
    ↓
查看说明、来源、文件、依赖和版本
    ↓
选择目标智能体（可多选，仅勾选用户指定项）
    ↓
选择作用范围：全局 / 指定项目
    ↓
展示每个目标路径、当前安装状态及同名冲突
    ↓
安装 → 下载/校验/写入进度 → 每个目标的结果
```

全局是该客户端跨项目可发现的位置；项目仅写入用户选择的项目目录。共享目录可能同时被多个客户端读取，界面须标明影响范围，不能暗示某个客户端独占。不存在客户端程序时可显示目录适配方案，但不能标注为「已检测到客户端」。

首次扫描不迁移用户已有文件，不强行导入一个新的中央仓库。首版是对本机文件的聚合管理；广场下载暂存后写入选择的位置，记录来源。只保存到 CueTuck 独立资源库、备份多机同步等能力不纳入首版。

### 独立副本与共享链接

首版使用独立副本，便于理解各客户端的本地修改，并减少 Windows 链接权限差异。代价是占用多份空间，更新需按安装位置处理。

后续可增加显式的「共享同一份」模式。共享模式更新一次会影响多个智能体，因此必须显示关联位置；不能静默把现有副本改成链接。发现现有符号链接时只读展示链接与目标关系，移除/更新交还原管理工具。

### 冲突、失败和重复操作

- 已安装相同版本：显示已安装，避免重复写入。
- 同名但来源不同：默认拒绝覆盖，展示两边来源与目标路径。
- 更新或重新安装：预览本地与待安装版本的差异；显式选择备份替换，不自动覆盖本地修改。
- 一次多目标：逐项预检查和返回结果，不承诺跨文件系统的整体事务。部分失败时保留已成功项，允许仅重试失败目标。
- 下载或校验失败：不写入目标；单目标写入失败不留下半个 Skill，原安装仍可用或可恢复。
- 写入期间防重复，导航须保护尚未完成的操作；普通列表加载可取消。
- 安装后提示按客户端实际机制刷新或重启；未经实测不声称已经出现在客户端菜单中。

## 5. 维护与目录管理

### 本机发现

启动本机页只扫描已知用户目录和用户登记目录。用户可添加项目或自定义 Skill 根目录；不默认遍历整块硬盘。嵌套目录、循环/失效链接、权限不足、数量/层级上限要可解释，不能用静默漏项冒充全部。

插件缓存内有文件不表示插件已启用，应显示「缓存中发现，启用状态未知」，与正常安装状态分开。只读内容允许查看；可执行的编辑、禁用、卸载不进入首版。

目录管理显示名称、对应智能体、实际路径、全局/项目范围、存在/不可读/只读状态。允许修改自定义目录信息和取消扫描登记；取消登记不删除目录内的文件，存在未恢复备份时提示保留恢复入口。

### 移除与恢复

从明确选中的安装位置移除，不默认删除所有客户端副本。操作前列出受影响位置，执行后保留恢复入口。备份应持久存放并可在应用重启后找回；恢复遇到同名内容拒绝覆盖。备份空间可见，首版不自动清空。

### 更新

仅有可验证来源的安装支持检查上游；无来源的本地内容标注「本地来源」。默认用户主动检查，不自动联网或覆盖。保留已安装版本、待更新版本以及上次检查时间。比较时识别本地修改；比较失败不显示「无需更新」。

## 6. 客户端兼容范围

路径依据核查于 2026-09-13，以下是候选适配合同，不是兼容测试结果。实际开发必须结合客户端版本和本机配置确认。

| 客户端 | 用户目录基线 | 项目目录基线 | 官方依据 |
|---|---|---|---|
| Codex / 标准共享 | ~/.agents/skills | .agents/skills | [Build skills](https://learn.chatgpt.com/docs/build-skills) |
| Claude Code | ~/.claude/skills | .claude/skills | [Skills](https://code.claude.com/docs/en/skills) |
| Pi | ~/.pi/agent/skills | .pi/skills | [Skills 文档](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/skills.md) |
| Cursor | ~/.cursor/skills | .cursor/skills | [Skills](https://cursor.com/docs/skills) |
| OpenCode | ~/.config/opencode/skills | .opencode/skills | [Agent Skills](https://opencode.ai/docs/skills/) |

补充边界：

- Codex 现有 $CODEX_HOME/skills（默认 ~/.codex/skills）作为兼容目录扫描；系统与插件目录只读，不把缓存当成安装目标。
- 适配器须识别客户端支持的配置目录覆盖；不能只硬编码 HOME。未知覆盖方式使用显式登记路径。
- Cursor、Pi、OpenCode 也可能读取共享目录或兼容目录；安装影响范围须反映共享关系。
- Pi 单文件 Markdown Skill、包配置的额外路径，与标准 SKILL.md 文件夹是不同形态。首版不伪装已覆盖，允许登记标准目录，后续增加专属解析。
- Grok 需要先确认具体客户端。现有同类软件列出了 Grok Build，但不据此猜测所有 Grok 客户端路径；列入下一轮官方兼容核实。
- 其他客户端先通过自定义标准目录接入，再逐个增加已验证适配器。Windows/macOS 必须分别验收；未测平台不能标成完整支持。

## 7. 技术与数据边界（设计建议）

前端复用 Vue 主壳和主题；本机读写交给 Tauri/Rust，列表索引与安装元数据独立于提示词内容。离线无需账号。浏览器预览明确无法管理本机文件。

核心记录分三类：来源（仓库/目录/版本）、安装位置（智能体/范围/路径/内容摘要/管理方式）、操作记录（安装/更新/移除/恢复结果）。来源不能覆盖用户原文件；自定义路径和凭据不上传广场。

包读取需要限制文件数量、单文件和总大小、递归深度及网络耗时；上限单文件 10 MiB、整包 25 MiB、1000 文件、4000 个目录/文件条目、16 层目录；扫描最多 20000 条目。写入先暂存、校验再落地，拒绝路径穿越、链接逃逸和特殊文件，不执行包内脚本。 YAML 引用和过深元数据不展开，改为原文展示。暂存预览在生成新预览时清理超过 24 小时的旧包，并最多保留 8 个；持久备份不自动清理。只下载所选 Skill 的完整目录；引用包外共享资料的内容提示不满足独立安装条件。

前端安装进度至少区分下载、校验、写入；提供当前文件数/总文件数和逐目标结果，不制造估算百分比。公开来源不可用时本机页继续工作。

## 9. Given / When / Then 验收场景

以下 MUST 为本轮验收要求，逐项测试后记录交付状态。

| 场景 | Given | When | Then / MUST |
|---|---|---|---|
| 导航分组 | 提示词列表有筛选或编辑草稿 | 切到 Skills 再返回 | 分组清楚，保留筛选；草稿受原有保护 |
| 离线扫描 | 标准目录中有普通、嵌套、不可读或失效链接 | 打开本机页 | 可用项展示，错误可见，不联网 |
| 同名与多处安装 | 同名不同来源，以及同源多个版本 | 浏览/筛选 | 不按名称错误合并；保留安装位置与版本差异 |
| 外部管理内容 | 插件缓存或链接已存在 | 查看并尝试维护 | 明确缓存/只读状态，不修改原管理关系 |
| 自定义目录 | 登记一个项目或 Skill 根目录 | 重启后再扫描或取消登记 | 登记持久化，取消不删除源文件 |
| 来源扩充 | 内置来源和用户自定义来源并存 | 搜索用途或切换来源后加载 | 显示匹配的来源及其真实目录；不自动下载包或修改已有安装 |
| 真实广场 | 仓库可访问或限流/断网 | 搜索、查看、重试 | 显示真实来源与搜索范围；错误不伪装为空 |
| 完整安装 | Skill 内含脚本、参考资料与资产 | 选择客户端/作用范围并安装 | 预览路径，完整落地并记录版本，不执行脚本 |
| 共享目录 | 目标目录被多个客户端读取 | 选择安装目标 | 显示共享影响，不声称仅选中客户端可见 |
| 多目标部分失败 | 两个目标可写、另一个失败 | 执行安装并重试 | 逐项反馈，仅重试失败项，不重复成功项 |
| 冲突与本地修改 | 同名 Skill 或安装后被改动 | 安装/更新 | 默认不覆盖；文件及正文差异可见；显式替换前可恢复备份 |
| 更新检测失败 | 有上游来源，网络失败 | 检查更新 | 保留版本，显示失败，不假装最新 |
| 包校验失败 | 越界路径、特殊文件或超限包 | 安装 | 拒绝；原文件完整；不遗留半安装 |
| 移除与恢复 | 同一 Skill 在多个客户端使用 | 移除选中位置，重启并恢复 | 仅影响指定位置；备份可找回；恢复不覆盖冲突 |
| 写入期间操作 | 安装尚未完成 | 重复点击或离开 | 防止并发冲突，保留结果和反馈 |
| 浏览器与平台边界 | 浏览器或未验证平台 | 打开管理功能 | 不伪造本机内容，不声称兼容已验 |
