## 交付原则

“全部完成”指范围内页面、后端、持久化、权限、客户端联动及验收证据齐全，不指菜单齐全。按 [计划深度 ADR](../architecture/decisions/0006-plan-altitude.md)，这里只排阶段和验收门槛；每个阶段开工前再写当期逐步任务，不提前编造未来文件路径或测试名。

每个可独立验收切片都执行：规格/接口与迁移设计 → 失败用例 → 实现 → 自动化/浏览器验收 → 同一提交记录证据。未实现项目不勾完成，不以旧 M6 完成记录代替本计划。

## 统一验收门槛

- 功能：提案每个编号逐项记录“已实现 / 已验证 / 外部待验证 / 未完成”，UI、接口与持久化不能拆开冒充模块完成。
- 安全：匿名/普通用户/审核员/运营管理员/所有者权限矩阵；直接 API 越权、跨账号、令牌撤销、秘密脱敏、重复提交与竞态。
- 数据：非破坏性迁移，保留现有账号/OAuth 配置/投稿；重启数据仍在；失败不产生半条业务记录或错误的成功审计。
- 联动：桌面/Web 的注册、投稿、广场字典/内容和权益规则真正生效；离线本地库与启动器不依赖管理服务。
- UI：真实浏览器逐项操作，至少覆盖宽屏、窄屏、键盘、列表分页及筛选、保存失败重试、未保存离开和会话过期；不靠截图代替功能验证。
- 工程：相关测试与构建、全端回归、文档门禁；每个切片提交代码与规格，不混入凭据、日志和测试截图。
- 外部：真实 OAuth 和邮件验收单独记录提供商/时间/结果，不记录秘密；缺凭据不能写“全部完成”。支付仅按 mock 验收。
