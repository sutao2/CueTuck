# 迁移本机 Google / GitHub OAuth 配置

- 日期：2026-09-13
- 状态：服务端配置已验收；提供商控制台与真实授权待用户完成
- 范围：用户授权从旧 PromptLauncher 的本机环境文件复制两家 OAuth 凭据，接入当前 PromptArk；不迁移账号、会话或其他密钥。

## 执行方案

1. 检查来源凭据存在及目标数据库覆盖状态，不输出凭据。目标没有数据库覆盖时使用现有服务端环境配置入口。
2. 写入 Git 忽略、0600 权限的 `backend/.env`，提供读取该文件的本地启动脚本；不把密钥放入前端、参数或日志。
3. 重启服务端，验证健康状态、提供商列表及授权跳转中 Client ID 与回调地址。真实授权仍需要提供商控制台登记当前回调并由用户完成授权，不把跳转成功视为登录成功。

## Given / When / Then

- GIVEN 本机环境文件包含两家凭据；WHEN 使用本地启动入口；THEN 环境配置生效，常规重启继续读取，文件及凭据不进入 Git。
- GIVEN 旧回调指向旧版本；WHEN 启用新版本配置；THEN 使用当前后端 callback，明确提供商控制台尚需登记，保留旧仓库文件不变。
- GIVEN 数据库存在管理端配置；WHEN 服务启动；THEN 继续遵循数据库优先规则，不绕过 owner 重认证改写数据库。

## 验收

- 旧版两家 Client ID/Secret 存在；当前数据库无对应覆盖设置，仅迁移这四项值，新回调统一为当前服务端地址。
- `backend/.env` 权限 0600，`git check-ignore` 确认忽略；凭据不进入提交、终端输出或进程参数。
- `bash -n backend/run-local` 通过；使用脚本实际重启服务，PostgreSQL、Redis、MinIO 健康检查全通过。
- 提供商列表返回 Google/GitHub；逐个检查 307 授权跳转，官方 host、来源 Client ID 与新回调均匹配，未跟随外部授权链接。
- 真实控制台注册状态、Secret 是否仍有效及外部账号授权未验证；旧环境回调为 8080 旧接口，提供商控制台应登记当前 8787 callback。
- `./scripts/docs-check` 与 `git diff --check` 通过。只提交启动脚本及运维说明。

运维配置流程见 [后端启动说明](../../backend/README.md)。
