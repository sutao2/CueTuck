## 行为与数据设计

- 唯一身份策略记录 registration_open，默认 true 保持升级前 OAuth 新账号可用行为。邮件注册还要求启用并配置 SMTP；关闭注册同时拒绝直接邮箱创建和新 OAuth 账号，已有账号/身份继续登录。后续站点设置复用此记录，不另存第二个注册开关。
- 公开 GET 身份选项；POST 发起 registration/reset，统一“若该邮箱符合条件，将发送邮件”的响应，不暴露是否已有账号。服务整体无邮件能力时统一 503；限流无账号存在性分支。邮箱规范化，新创建前按小写邮箱串行化并检查已有大小写变体，不改写旧账号。
- 使用 OS 随机 256 bit 验证凭据，仅 SHA-256 摘要作为验证索引；邮件载荷加密。30 分钟有效，单次消耗，同邮箱同目的重发使旧凭据失效；新密码只在确认阶段发送与存 Argon2id，未验证前不创建账号/存储明文密码。确认不自动签发会话，用户回到常规登录。
- 验证页面让用户粘贴邮件中的凭据，不放 URL 查询或 localStorage，避免浏览器历史/服务访问日志泄漏。邮箱、凭据、用途及新密码一起确认，邮件固定模板提示过期时间与防诈骗。
- owner 当前密码确认后可邀请新邮箱成为 admin/reviewer；不允许匿名管理员注册，也不邀请 owner 或覆盖已有账号。邀请接受时复核邀请者仍为未停用 owner；撤销/重复/过期不创建账号。已有用户提权继续走已验证的用户管理流程。
- admin 仅能发起普通用户的重置，owner 可发起未停用账号重置；后台不返回凭据或设置目标密码。用户自己凭邮件重置后撤销全部会话，失败事务不得同时消耗验证码而未改密码。禁用与角色变化在事务内复核。
- 发起/确认采用全局/直连 peer/邮箱频控；每天同邮箱最多 5 封验证类邮件，重复发送响应不泄露账号。对无效/过期/已用令牌统一错误。公共请求结果不返回 token、邮箱是否存在、角色或投递 ID。
- 业务、挑战凭据、邮件入队与成功审计同事务；邮件 worker 不直接修改身份。关闭邮件不会恢复过期凭据；不为验收给现有用户发信。

## 任务与验证

1. 先写隔离 PostgreSQL 测试：枚举响应/关闭注册/无 SMTP、一次性/到期/重发、改密撤销/并发回滚、邀请撤权/已有账号防覆盖、OAuth 直连新账号门禁。
2. 增量表与接口；重用既有令牌/角色/邮件事务模式，保护历史账号和固定角色。
3. 管理端注册开关、邀请列表/创建/撤销、用户发起重置；所有高敏输入不持久化浏览器。
4. 桌面与 Web 登录处提供注册、忘记密码、验证/接受邀请；清晰忙态、错误、密码确认与回到登录，桌面原生请求不修改 Refresh 存储规则。
5. 全端自动化、浏览器与 native 编译、文档检查后正常提交。真实邮件与外部 OAuth 验收单列。

## Given/When/Then

- GIVEN 注册关闭或验证邮件未配置；WHEN 匿名直接请求注册或首次 OAuth 创建；THEN 不创建新账号，原账号仍能登录。
- GIVEN 已用/过期/撤销凭据或邀请者已被撤权；WHEN 完成确认；THEN 不改账号、不发会话、不给出凭据敏感细节。
- GIVEN 密码重置与旧密码登录/会话刷新并发；WHEN 事务提交；THEN 旧会话不能复活，令牌消费/改密/审计原子一致。
