## 行为和安全边界

- 数据库配置增加 revision（旧配置为 0）；owner 保存要求当前密码、版本匹配，操作者复核/配置/失效状态/审计同事务。空 Secret 保留原值，成功清空输入。配置来源仍区分数据库/环境变量/未配置，数据库关闭覆盖环境。
- “验证授权”是独立显式流程，不注销管理员、不创建用户、不绑定身份、不签发客户端会话。只有实际交换授权码并取得提供商验证过的邮箱，才算本次配置授权成功；不把内存 mock_users 当真实成功。
- owner POST 验证入口生成 OS 随机 256 位 state，仅存 SHA256 索引、发起人、提供商、配置指纹、状态/原因/时间，10 分钟过期，原子消费且不可重放。返回官方授权 URL，在新窗口打开；复用已有后端 callback，使用专用 state 前缀与普通登录分离。
- 当前配置指纹涵盖凭据和回调，外部调用前后均核对；旧验证或旧回调不能使新配置变成已验证。配置保存会使 pending/verifying 及旧成功失效；重新发起撤销同提供商旧待验证，避免迟到回调覆盖新结果。
- callback 不要求浏览器传管理令牌，依靠随机一次性 state；最终事务再次确认发起人仍是有效 owner。只返回固定成功/失败 HTML，无 token、授权码、提供商原始响应或测试账号邮箱。响应 no-store/referrer-policy no-referrer，页面提示回管理页刷新结果。
- GET 管理配置附当前配置的最近验证状态/时间/固定失败原因，未发起、等待、处理中、过期、取消、配置变化、提供商拒绝/请求失败、真实成功分开；不永久缓存环境凭据验证结果。
- 出站只用固定官方端点（测试可注入 loopback），禁止重定向，整个链路最多 25 秒，每响应最多 256 KiB，拒绝非 2xx、未验证邮箱、空 UID，失败不记录响应正文。
- 前端只在已保存且启用且无草稿时验证；校验返回 URL 必须是 Google/GitHub 官方授权路径。新窗口有 noopener/noreferrer；提供显式刷新结果入口，窗口被拦截有可见链接，无自动轮询引发登录节流。

## 实施和验收

1. 版本化保存与脱敏审计，增量验证记录表和严格 owner/重认证；不修改现有真实配置。
2. 一次性独立验证 callback 和配置指纹，限时有界真实提供商读取。
3. 前端状态、密码录入、保存冲突草稿、验证入口/结果刷新；完善操作文案。
4. 隔离测试 CAS/权限/审计回滚、state 消费/过期/错误、配置变更、模拟账户不得认证成功、真实 loopback token/profile 成功且不创建账号；前端测试、构建、只读浏览器和文档后正常提交。

## Given/When/Then

- GIVEN 配置仅保存或缺失凭据；WHEN 查看状态；THEN 不标真实授权成功，未配置不能发起验证。
- GIVEN 正在验证的配置被改动或管理员撤权；WHEN 回调完成；THEN 不更新新配置为成功、不创建会话或账号。
- GIVEN 随机 state 已消费/过期或提供商返回未验证邮箱/错误；WHEN 回调；THEN 拒绝重放或显示固定失败原因，不泄露外部正文。
- GIVEN 隔离提供商返回有效验证邮箱；WHEN 完成显式授权；THEN 记录成功与时间但不提升权限、不建立账号关联。
