# Windows 升级后的旧图标调查

## 设计（已完成）

用户报告 Windows 桌面与任务栏在 beta.39 中仍显示旧双环，设置确认版本为 beta.39。公开 beta.39 可执行文件的首个图标资源为蓝色卡片，需验证已安装的快捷方式、系统外壳和运行中窗口实际使用的图标。

## 验收场景

- Given 安装公开双环版 beta.37 并启动，When 在相同目录升级到公开 beta.39，Then 核对 EXE 版本、快捷方式目标及图标位置，并导出外壳与窗口图标，确认实际升级结果。
- Given 定位到旧图标来源，When 修复，Then 使用相同升级路径复验；发布附件身份可用公开摘要核对。

## 计划

在 Windows 临时验收环境安装旧版与已发布的 beta.39，保留前后图标与快捷方式属性作为证据，再决定所需修复。

## 已复现

公开 beta.37 在同一目录升级到公开 beta.39 后，可执行文件与运行中窗口已为蓝色卡片，系统外壳与桌面快捷方式仍读取双环缓存。文件变更通知与缓存通知未能使本轮读取的图标更新。接下来验证使用按图标内容生成的独立 ICO 路径更新指向本应用的桌面、开始菜单和任务栏快捷方式。

## 修复验收

[旧版升级复现](https://github.com/sutao2/CueTuck/actions/runs/43799782055)中窗口图标已为蓝色，但外壳和快捷方式仍为双环。[修复验证](https://github.com/sutao2/CueTuck/actions/runs/43801098781)使用图标内容摘要命名独立 ICO，更新指向当前可执行文件的快捷方式后，导出的桌面和开始菜单图标均恢复蓝色卡片。提供独立 Windows 修复脚本，可处理指向同一可执行文件的桌面、开始菜单及已固定任务栏快捷方式。
