# 官网产品表达与视觉优化

## 方案

用户要求官网更专业，并以 ChatGPT 官网为视觉参考。沿用现有静态站点、公开广场和服务器部署，仅调整首页、下载页及共用导航/页脚；不修改桌面端和公开数据逻辑。

参考：[ChatGPT 产品官网](https://chatgpt.com/overview/)的公开页面内容与产品叙事。自动化浏览器访问该站遇到验证页面，因此不声称已做像素级视觉对照。

1. 先明确[官网规格](../specs/website/spec.md)：以中性白灰、清晰字号层级、充足留白及真实产品画面建立产品官网的视觉节奏，保留 CueTuck 品牌。
2. 重排首屏与功能叙事，统一下载页、按钮和导航；保留搜索/填写截图切换、真实广场与 Skills 入口、现有 beta.25 下载地址。
3. 在 1440、960、390px 检查首页/下载/广场/Skills 的布局与操作；验证键盘、截图切换、公开数据及现有模块测试。
4. 独立切片提交，白名单构建后切换官网静态目录；保留旧目录回退，不更改后端与持久卷。

## 场景

- Given 初次访问 When 阅读首屏 Then 能理解 CueTuck 是桌面提示词启动器，并找到下载与广场入口。
- Given 预览区 When 鼠标或键盘切换搜索/填写 Then 显示对应真实截图且选中状态同步。
- Given 手机、平板或桌面 When 浏览与切换路由 Then 导航和主要操作可达，无横向溢出，截图不拉伸。
- Given 下载页 When 选择平台 Then 指向已发布 beta.25 对应平台资产，签名限制与架构说明仍明确。
- Given 广场与 Skills When 导航、搜索或打开详情 Then 保持真实数据和原有操作，页面失败不显示虚构内容。

## 验收

- 首页采用居中标题、中性主操作、浅色产品展示区及真实截图；功能内容按使用、整理、发现展开，下载页和导航/页脚统一。
- 7 项公开数据模块测试、JavaScript 语法检查、文档门禁与 diff 检查通过。
- Playwright 验证首页、下载、广场、Skills 四页 × 1440/960/390px 共 12 组布局无横向溢出，每页仅一个主标题；双平台下载保持 beta.25。
- 鼠标和键盘切换搜索/填写截图通过。通过只读代理读取线上广场 24 条、Skills 20 条；真实搜索“鹈鹕”、提示词正文、Skills 原文和列表视图均可用，无页面脚本异常。
- 已逐屏检查桌面首屏、发现区、手机首屏/资料库及双尺寸下载页。截图位于 `output/playwright/website-polish-*.png`；完整长截图工具出现重复拼接，视觉验收使用逐屏截图和实际 DOM 尺寸。
