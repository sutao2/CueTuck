# macOS 更新后的钥匙串重复授权

状态：方案已确定，验证中。

## 证据与范围

用户确认主要发生在更新或重装后。beta.17 使用 ad-hoc 签名，DR 为单一 cdhash。只读 ACL 检查发现登录条目保留 7 条 CueTuck 授权，只有当前版本匹配；运行中程序与安装路径身份一致，签名完整。AI 条目为独立授权。保留 PromptArk 服务名兼容旧数据，不删除用户凭据、不扩大访问名单、不保存明文令牌。

## 实施方案

Mac 预览构建必须显式复用固定签名身份，缺少身份时阻止构建而非回退 ad-hoc。无 Developer ID 时，先在隔离环境验证固定自签名证书的 DR 和钥匙串跨版本识别；私钥仅本机受限目录，构建钥匙串独立，不修改系统信任、不允许所有程序访问钥匙串。已有 updater 签名仍独立保留。正式发行继续要求合规 Developer ID/公证，不将自签名视作 Apple 认证。

## 验收

- Given 两份二进制内容不同但相同 identifier 和证书 When 签名 Then DR 相同，互相满足指定身份。
- Given 隔离钥匙串由版本 A 写入测试凭据 When B 在禁止交互时读取 Then 成功；不同证书的版本不能读取。
- Given Mac 预览未配置身份或身份是 `-` When 构建 Then 失败且解释固定签名要求；Windows 构建不要求 Apple 身份。
- Given 老 ad-hoc 应用升级 When 首次访问旧凭据 Then 可能需要用户再次授权；不得自动绕过或声称迁移无提示。

只在隔离验收通过后使用固定身份生成本机修复包；不覆盖已发布 beta.17 附件。记录测试结果和仍需用户首次授权的边界。


## 验证进展

固定自签名证书 SHA-1 标识 `D175B21331B6E39F171EE7FB16E4227A6C6A64EA`（公开证书指纹，不是私钥）。隔离钥匙串：版本 1 写入、不同二进制版本 2 读取均成功；相同 identifier 的 ad-hoc 版本 3 返回 -25293，禁止交互且没有授权弹窗。新旧签名 DR 相同，约束 identifier 与证书叶子指纹，未使用仅凭名称的宽泛规则。临时钥匙串已清理，用户搜索列表恢复，系统信任未修改。

9 项预览环境/门禁测试通过，缺少材料和临时签名被拒绝；显式身份、Windows 与独立 updater key 保持兼容。准备构建本机修复包；beta.17 公开附件保持原样。
