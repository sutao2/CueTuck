# 广场卡片窄列修复

状态：已修复并验收，未打包发布。

## 方案

1. 广场虚拟网格的最小列宽从 240px 调整为 280px，窄容器仍可缩为一列；本地瀑布流不变。
2. 卡片操作保持文字单行、图标不压缩；底栏在极窄容器允许整体按钮换行，不拆中文字。固定虚拟行高保持一致。
3. Chromium 用真实工作台样式和虚拟网格组件复现 240px 问题，验证单条合集、多条混排、窄窗与缩放等效宽度；运行相关测试及构建后提交。

## 验收场景

- Given 宽屏仅一个合集结果 When 查看卡片 Then 列宽至少 280px，选择提示词文字单行，操作无重叠。
- Given 多条图文结果 When 改变窗口宽度或缩放 Then 列数和虚拟行计算一致，操作可见，页面无横向溢出。
- Given 列表视图 When 切换 Then 保留原列表排列，不受卡片列宽影响。

边界：本机 Chromium 可覆盖 WebView2 的布局引擎，不能替代 Windows 原生安装实测；本轮不自动发布新版。

## 验收结果

- 使用真实 WorkbenchShell、Windows host 和隔离广场数据，在 1856px Chromium 复现：原卡片 242px、主按钮 45px 高（两行）；修复后卡片 293px、主按钮 30px 高（单行）。
- 1856 / 1536 / 1280 / 960 / 800 / 600 / 360px 单条卡片无按钮越界；48 条混合提示词/合集在六档宽度与滚动 1800px 下虚拟列数正常，按钮无压缩/裁切。1536 / 1280 CSS px 对应 1920 物理像素在 125% / 150% 下的布局宽度，并非 Windows 系统实测。
- 1280px 列表仍为单列 116px 行高，无横向溢出。固定本机测试图片已加载，截图：`output/playwright/windows-card-width-fixed.png`。
- WorkbenchShell 与 squareWindow 共 109 项测试通过，生产构建通过；临时页面、浏览器和预览服务已清理。
