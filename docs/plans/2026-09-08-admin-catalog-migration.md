# 分类和模型引用迁移

| 字段 | 值 |

## 设计

- owner/admin 明确选择同类启用目标、填写原因、确认源/目标版本后执行迁移并移除源字典项。只作用于公开 square_items 元数据（含合集成员）；源保留墓碑和持久化重定向。投稿历史保持原值，后续人工通过时解析重定向到当前分类/模型。
- 迁移大分类时，仅允许另一个启用大分类作为目标，并把原子分类重新挂接到目标；若同名子分类冲突则拒绝，先改名/单独迁移，不静默合并或形成第三级。迁移小分类可以选择有效大/小分类。目标不能是源或其子分类。
- 当前审核 Skill 仍引用源时拒绝迁移并提示先由所有者在 Skills 页更换适用分类；不借运营迁移越权修改安全策略。历史 Skill 配置保留不变。
- catalog_redirects 的终点永远是未删除项。后续终点迁移时同步压平已有重定向；安全删除将入站重定向也计为引用，不能删掉历史终点。禁止复活源 ID。
- 已提交的新稿审核上架必须持有同一 catalog 锁；人工通过映射分类/模型及成员。AI 审核期间相关字典迁移会导致转人工，不能把按原分类审核的结果当新分类的安全结论。新投稿仍须选择当前有效字典，旧 ID 不自动接纳。
- 操作者行锁 → catalog 锁 → 内容行；公开内容版本递增，旧编辑草稿冲突。移除、成员/分类迁移、重定向及审计同事务；审计保留源/目标、原因、变更条目数/子分类数，不记录正文。
- 列表支持大分类折叠/展开；搜索时展开匹配项，模型按类型筛选。迁移入口在编辑区，提交中禁止重复和离开，失败保留选择；源有引用不再只有不可点击的删除按钮。

## 实施与验证

1. 增量建重定向表，迁移 API 与解析辅助函数；同事务复核身份、版本、层级、目标有效性和当前 Skill 引用。
2. 人工通过与 AI 完成路径接入，确保并发迁移/通过/内容编辑不写回旧值；验证原始投稿快照不变。
3. UI 目标/原因/确认、冲突重试、分类折叠和模型类型筛选。
4. 权限/大分类冲突/历史保护/连续迁移/审计回滚/并发测试；前端测试构建、真实浏览器只读和窄屏；更新合同/规格后正常提交。

## Given/When/Then

- GIVEN 源分类同时被公开合集、历史投稿与子分类引用；WHEN 确认迁移到有效大分类；THEN 公开引用和子分类迁移，投稿快照不变，后续上架解析到新终点。
- GIVEN Skill 仍引用源、同名子分类冲突或目标已变更；WHEN 迁移；THEN 明确拒绝且无部分写入，用户可先处理冲突。
- GIVEN A→B 已迁移，后来 B→C；WHEN 查看公开内容或审核旧稿；THEN 使用 C，不留下悬空引用；C 不能直接删除。
- GIVEN 迁移审计失败或旧版本编辑并发；WHEN 提交；THEN 回滚迁移或返回版本冲突，不改本地与正文。
