# 质量约定

| 字段 | 值 |
|---|---|
| 状态 | 现行 |

## 文档

- 现行事实只写一份。
- 代码示例必须能运行或标明「目标伪代码」。
- 禁止 TBD、TODO、稍后补写作为合并内容。
- 中文正文，英文标识符。

## 规格

- 需求用 MUST / MUST NOT / SHOULD。
- 每个需求至少一个 Given/When/Then。
- 场景必须可写成测试。

## 代码（自 M1）

- 先失败测试，再最小实现。
- 与规格冲突时改代码或先改规格并说明原因，不得两边各写各的。
- 不引入与当前里程碑无关的依赖。

## 评审

- 行为变更看规格 diff。
- 结构变更看架构与 ADR。
- 只改文案且不改行为可以不新增 ADR。
