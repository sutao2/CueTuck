# 参考图下载速度与进度

状态：Mac beta.4 已公开，安装待解锁；Windows 构建验证进行中。用户明确要求优化下载速度。

## 方案

1. 每条提示词最多同时下载 3 张参考图；原生端一次批量命令共用同一 HTTP client/连接池，每批重新读取代理配置。浏览器同样限制并发。保持原图顺序、6 图上限、单图 5 MiB、合计 20 MiB、白名单/无凭据/无重定向和完整导入。
2. 原生批量命令通过独立 Channel 上报已完成张数；列表、详情和补图显示「参考图 n / total」，保存阶段不冒充完成。失败取消剩余任务，不继续排队，不导入半份内容或上报下载次数。
3. 测试并发上限、乱序完成后的结果顺序、错误中止、进度隔离、旧副本补图与原子性；运行全量前端及原生回归，构建新预览版并安装验证。仅通过读取公开图/隔离库验证，不制造生产统计。
4. 此轮不迁移第三方图片、不修改系统代理、不跳过慢图。有限并发可减少串行等待，不能承诺消除第三方源站的网络波动。

## Given / When / Then

- GIVEN 一条有 6 张图；WHEN 下载；THEN 同时最多 3 个图片请求，共用本批原生连接池，返回顺序与源图一致。
- GIVEN 完成顺序不同；WHEN 图片依次完成；THEN 对应提示词的完成数单调递增，列表与详情一致，其他下载不串进度。
- GIVEN 任一图片失败或超限；WHEN 检测到错误；THEN 中止剩余请求，不启动排队图片，本地库不出现部分副本，可重新尝试。
- GIVEN 网络耗时不可确定；WHEN 尚未完成；THEN 展示真实张数，不显示虚假百分比或提前宣布成功。
- GIVEN 用户修改手动/系统代理；WHEN 新下载开始；THEN 新批次读取当前配置，不永久复用旧代理客户端。
