# 变更提案：M8 设置对齐原型

| 字段 | 值 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-08-23 |
| 影响规格 | [settings](../../specs/settings/spec.md) · [launcher](../../specs/launcher/spec.md) · [variables](../../specs/variables/spec.md) |

人要求把原型设置信息架构写入现行合同与后期计划。本提案只增加，不缩小 M2 已交付设置，也不缩小 [M7](../m7-contract-gaps/proposal.md)。

实现仍按 [M8 计划](../../plans/2026-08-23-m8-settings-ia.md)。M7 关闭前不得改设置相关应用代码。

## 为什么

原型设置有十类。M2 只落地四类本机行为，同步/账号是占位；网络与代理、更新、AI 与模型、隐私与安全连导航都没有。路线图在 M7 之后也没有设置对齐。合同与原型不一致，且后期计划漏项。

## 做什么

1. 设置左侧固定十类：常规、账号与广场、快捷键、同步、AI 与模型、数据与备份、网络与代理、外观、隐私与安全、更新。
2. 保留已有 JSON 导入导出、库文件备份恢复、浅色/深色、启动器唤起快捷键。
3. 增加本机可实现的行：开机启动、托盘、用完关启动器、新建/粘贴最近快捷键、打开目录、ZIP、自动备份、跟随系统、语言、双语、密度、本机模型目录、广场访问开关、清除使用历史等。
4. 云同步、自动更新安装、OAuth、作者主页编辑在未立项前必须仍出现对应行，标明尚未提供，不得假装接通。
5. 当前账号接到已有邮箱密码登录，不绑定未选定的 QQ / LinuxDo / Google。

## 不做什么

- 不删除 M2/M4 已有设置行为
- 不缩小或不跳过 M7
- 不实现云同步引擎、应用自动更新安装、OAuth
- 不把启动器改成覆盖层，不让启动器请求广场
- 不在 M7 关闭前写设置应用代码

## 依赖

M6 已关闭。M7 仍是当前实现里程碑。本提案已并入规格；应用实现等 M7 关闭后执行 M8 计划。
