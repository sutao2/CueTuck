# 滚动流畅度

状态：滚动路径优化与本机浏览器对照、前端回归和 macOS 构建完成；当前用户原生进程未重启，原生掉帧反馈待复验。

## 范围与步骤

用户反馈广场、本地、详情与编辑均有掉帧感。本轮检查共用绘制和列表滚动路径，不把单一浏览器帧率当作原生流畅度保证。

1. 基线：隔离浏览器以相同窗口、数据与滚动轨迹记录广场、本地、长正文详情及编辑滚动帧间隔与布局样式读取；组件测试复现小幅滚动触发不必要卡片渲染。
2. 减少开销：虚拟列表仅范围变化更新可见卡片；列宽/间距测量只在布局失效时进行，滚动保持位置正确；停用非虚拟列表无效监听。移除固定筛选栏背景模糊，图片解码异步。仅实施测量和代码证据支持的改动。
3. 验收：同条件复测、滚动后打开/返回、缩放/列表切换、追加与末页、卸载清理；前端回归、文档门禁、macOS 打包，完成后提交。

## Given / When / Then

- GIVEN 可见行范围不变 WHEN 多次小幅滚动 THEN 不重复渲染卡片槽，不逐帧读取网格计算样式。
- GIVEN 视口、列宽、条目或显示状态改变 WHEN 再次滚动 THEN 可见范围与占位准确；续页和详情返回位置保持原行为。
- GIVEN 本地分页或隐藏内容 WHEN 滚动其他页面 THEN 不为非活动虚拟列表安排无效滚动任务。
- GIVEN 固定筛选栏及带图内容 WHEN 滚动各页面 THEN 筛选栏保持不透明且可读，图片使用异步解码；没有新增空白、布局跳动或不可达内容。

## 验收记录

- 组件回归先失败再通过：20 次同一可见范围内的小幅滚动，卡片槽调用从 300 次降至 0 次；另覆盖调宽、列表切换、网格起点变化、替换数据、非虚拟模式不监听与卸载取消任务。
- 同一 Chrome、1280×850、每场 120 帧/每帧 35px：广场网格/列表的网格计算样式读取均从 117 次降为 0；挂载数分别仍为 21/12，scrollTop 与总高度一致。本地 48 卡、400 行详情、编辑外层及正文内部均完成滚动。
- 前后各场 p95 帧间隔均为 16.7–16.8ms，超过 25ms 的间隔均为 0。浏览器基线未复现用户报告的原生掉帧，因此仅确认减少滚动开销，不宣称实际 FPS 已提高或原生问题全部消失。
- 实施：保持可见范围对象稳定，避免重复卡片渲染；列样式只在布局/数据失效时读取；保留滚动时网格起点测量以支持页头变化；本地分页不挂载无效监听；固定筛选栏改为不透明背景，列表/附件/详情图片异步解码。
- 73 个前端测试文件、474 项通过；docs-check（262 份 Markdown）、diff-check 和 macOS 调试构建通过，保留 9 条既有 Rust 警告。本轮无原生命令或存储修改。
