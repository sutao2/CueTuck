## 范围与步骤

1. 使用随机 PostgreSQL schema、临时浏览器和独立 API/前端端口串联注册、登录、新建附件、投稿、管理审核、广场下载、变量填写及复制。真实后端和本机 MinIO；邮箱仅读取隔离测试 outbox，不发送外部邮件。浏览器只替换原生登录/邮箱入口为真实 HTTP，剪贴板使用可断言的隔离适配器；不声称原生窗口或操作系统权限已验。
2. 发现问题先补回归再修复，更新相关规格与索引；测试仅清理该次随机 schema 及其新建对象，保留用户实例。
   初始化检查发现开发重置清单遗漏 `ai_jobs`：补充「普通迁移保留任务、显式开发重置清除旧任务并重建外键」回归，只在隔离 schema 验证。
3. 本地集中回归通过后提交并普通快进推送当前分支到已配置远端；若远端有不同历史，不强推。查看对应提交 CI，能在当前范围修复则回归后再推送；权限/额度等外部限制如实记录。

## Given / When / Then

- GIVEN 隔离新账号；WHEN 请求注册验证码并确认后登录；THEN 账号为普通用户，不能进入管理 API。
- GIVEN 本地提示词有变量和附件；WHEN 选择文件投稿；THEN 上传和快照落库，审核前匿名读不到公开文件。
- GIVEN owner 在管理端审核通过；WHEN 客户端检索下载；THEN 正文、文件字节和哈希一致，再次下载不产生重复条目。
- GIVEN 下载的提示词含变量；WHEN 填写并复制；THEN 内容正确替换，取消/失败不丢失本地内容。
- GIVEN 全部本地门禁通过；WHEN 普通推送；THEN 记录精确远端提交及 CI 状态，不把排队或失败写成通过。
