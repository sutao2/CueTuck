## 步骤与验证

1. 增量创建 reports（公开目标 ID、举报者、类型、原因、状态、优先级、负责人、版本、真实时间）及 report_events；安全规则保存版本化配置。旧库不清空，不扫描私有库。
2. 先写真实 Postgres 用例：普通登录用户仅举报在线广场条目、同人同目标未结案去重、每日上限 20；不得查看他人举报；管理读写仅 owner/admin。
3. 管理员按关键词/状态分页，详情查看目标公开快照及规则命中；处理/分派/驳回/下架结案必须填写原因，带 revision；已结案不能再写。下架、事件、审计同事务，并发只成功一次。
4. 安全规则支持分类、字面关键词、风险分数、启停与版本保护；不用用户正则避免计算滥用。测试只执行本地确定性匹配，不调用 AI，返回规则及命中词，禁止将无命中解释为内容安全。
5. 管理端补两页及权限导航，错误/空/加载/草稿保护、危险操作确认和搜索分页；公开客户端补举报入口及本人状态。导出限制最多 500 条、只含必要元数据、不含正文，记录审计。
6. 后端、组件、真实浏览器、构建和文档验证；正常尝试提交，提交门禁不通过不伪造授权，同时继续后续切片。

## 场景

- GIVEN 登录用户举报在线条目；WHEN 重复或并发提交；THEN 只保留同一未结案举报，不泄露其他举报者。
- GIVEN 旧处置版本或已关闭案件；WHEN 管理员提交；THEN 返回 409，不重复下架或增加历史。
- GIVEN 审计写入失败；WHEN 下架结案；THEN 内容、案件、历史均回滚。
- GIVEN 停用规则或空关键词；WHEN 测试；THEN 停用项不匹配，非法配置拒绝；结果标识本地规则而非 AI。

## 数据边界

举报目标为广场提示词或合集；用户描述不自动采信为违规证据。原因最长 1000 字。普通用户只能看到自己的案件状态和结案原因，不含管理员邮箱、内部过程或其他举报者。规则由 owner/admin 维护；不加入自定义角色。操作复核当前数据库会话/角色，规则匹配只使用公开正文/标题/合集成员。
