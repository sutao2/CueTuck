# 内容版本与更新

状态：已随 beta.34 于 2026-10-16 发布上线，验收见[发行记录](../../plans/2026-10-16-beta34-release.md)。

提示词、合集与社区 Skill 保留稳定公开身份。公开版本采用单调递增编号和不可变快照；当前指针只在审核通过的同一事务中前进，收藏及统计仍引用原 ID。历史版本记录提交标识、基准版本、更新说明及发布时间。相同提交只可对应相同快照，过期基准不得覆盖已发布新版。

旧公开内容补齐 v1 时不修改旧表或合并同名内容；重复迁移不改变已有版本。旧本地副本无确切下载快照时标记未知，不以当前远端内容倒推基准。作者只能更新本人内容，待审、驳回或撤回候选不改变当前公开内容；内容整体下架仍限制历史读取。历史附件须跟随快照保留，不能被清理任务提前回收。

本地下载记录来源 ID、所装版本及基准快照。更新前比较基准、本地与远端，用户明确确认；本地修改冲突必须保留或另存，只有显式备份替换可覆盖。应用/恢复时再次检查本地摘要，防止预览后修改被覆盖。合集成员使用稳定标识关联附件；旧数据不按名称、顺序猜配。社区 Skill 分安装位置更新并沿用路径校验、完整包校验、备份与恢复，不改写外部管理链接。

详细 Given/When/Then 与各阶段验收见[实施计划](../../plans/2026-10-15-content-versioning.md)。

已实现接口：`POST /v1/publications` 与 `POST /v1/skills` 可选 `revision`（content_id、base_version、change_note、request_id），不传时保留首次投稿行为。`GET /v1/content/:kind/:id/versions` 返回最近 100 条版本摘要，`.../versions/:version` 返回指定快照；均受当前公开状态约束。合集成员可选 member_id，旧缺失值保留未知，不能据此猜测关联。

本地实现：SQLite 新增 downloaded_content 和 content_update_backups，不改写旧行。更新请求携带预览摘要，在立即事务内再次核验；备份与覆盖原子提交。备份恢复为独立副本，不覆盖之后的修改。日常使用次数不作为内容冲突，也不因更新重置。旧 JSON 导入或同步副本缺少来源基准时保持未知；整库 SQLite 备份包含新表。合集旧快照缺少任一成员 ID 时仅允许另存，未修改的已移除远端成员可删除，本地修改过的移除成员以及本地新增成员保留。

社区 Skill 在安装记录及备份中保存独立社区 ID/版本，未关联的旧记录不猜配。同文件内容的新版也推进来源版本；过期预览不能倒退来源版本。更新必须保持原包目录名，并复用既有文件摘要复核、路径保护、替换确认与备份恢复。GitHub 来源流程保留。

固定版本附件使用原公开地址加 `?version=N`，仍复核当前上架权限；版本快照引用的文件不可清理。

已关联且版本已知的下载内容在本地页面后台只读检查版本，显示“有新版”角标；提示词、合集点击进入比较，社区 Skill 在各安装位置确认更新。进入页面、回到前台及可见页面每五分钟检查，相同来源合并请求、最多三个并发、缓存五分钟；关闭广场访问或离线不检查，会话变化丢弃旧结果。未知基准不猜测版本，GitHub 来源仍手动检查。后台不下载内容、不覆盖本地修改；替换仍须用户明确确认并遵循既有备份与并发修改保护。

客户端入口：作者在“我的发布”选择发布更新或查看版本历史；历史内容重新提交仍走审核并产生新版本。Skill 发布表单可选择已有作品。桌面本地提示词提供“下载更新”，展示本地/远端/下载基准，替换必须二次确认；旧来源仅能另存。合集再投稿从已记录的来源映射保留公开成员标识。审核台展示更新目标、基准版本和说明。

作者可通过 `POST /v1/publications/:id/withdraw` 撤回本人的待审更新候选；撤回不修改当前公开版本。已批准的 Skill 更新候选不能作为下架入口，需操作原公开作品。

更新角标随 beta.35 发布，双平台安装和公开更新验收见 [beta.35 发行记录](../../plans/2026-10-16-beta35-release.md)。
