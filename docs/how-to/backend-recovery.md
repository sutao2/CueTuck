# 后端备份与恢复

本页适用 PostgreSQL 后端。管理台「系统状态」仅做只读检测，不执行服务器命令。正式恢复会替换服务数据，必须取得明确授权并核对目标；不要使用 `PROMPTARK_RESET_SCHEMA=1` 修复已有业务库。

## 备份单元

同时保护下列内容，并记录同一备份时间、应用提交版本、数据库版本与校验和：

- PostgreSQL 自定义格式逻辑备份，包含账号口令哈希、令牌、公开快照、配置、审核和审计记录。
- 实例正在使用的加密密钥文件。密钥与备份分开加密保管，限制权限；缺失时不能生成新密钥替代，否则 OAuth、AI、SMTP 等密文无法恢复。
- 对象存储桶的对象及元数据；数据库备份不包含图片二进制。
- 部署配置和所需秘密，通过秘密管理设施备份，不提交 Git、不贴到日志或工单。

Redis 用于缓存/限流，不作为账号、权益、审计或邮件队列真相。恢复后清理隔离环境缓存，而不是复用生产缓存。

## 正式操作的检查顺序

1. 核实源/目标实例和授权范围，安排维护窗口，停止所有写入及投递 worker；保留当前环境的回退备份。离线导出的令牌和密码哈希同样属于敏感数据。
2. 使用匹配数据库主版本的 `pg_dump --format=custom --no-owner --no-privileges`，明确数据库和 schema。认证放在权限受限的服务配置，不放在命令行/终端历史。完成后检查退出码和校验和。
3. 在新建的空数据库执行 `pg_restore --exit-on-error --no-owner --no-privileges`；先核对 `pg_restore --list`。不要对现有业务库使用 `--clean` 或覆盖恢复。同步恢复对象存储到独立桶，装入配套密钥与配置。
4. 首次启动隔离实例时关闭真实投递/支付和其他外部副作用，使用独立 Redis。核对关键表行数、所有者角色、合成/授权测试账号登录、公开快照、图片可读性与配置可解密；确认错密钥拒绝。已有真实密钥不要打印，也不要通过真实用户登录来验证密码。
5. 记录验证、停机点及回退方案，取得正式切换批准后才切换连接。恢复业务前复核未完成邮件任务、一次性挑战和外部操作，避免重复投递；必要时由所有者撤销会话。观察状态和失败审计。

## 可重复的隔离数据库演练

本地 `backend-db-1` 必须是 PostgreSQL 16 开发容器，`pl` 可创建临时库；默认连接 `127.0.0.1:5432/promptark`。不对其他数据库地址运行此特定演练。

```bash
cd backend
cargo test --lib isolated_postgres_restore -- --ignored
```

测试新建随机 `security_…` schema，写入合成账号、公开快照及随机密钥加密的样本。仅 dump 该 schema，经内存传递给独立随机 `recovery_…` 数据库的 `pg_restore`。核对账号正/误密码、关键表数量、快照和正/误密钥，最后仅移除本次创建的 schema 与临时库。无真实业务备份、密钥或原始内容输出。失败时检查是否留有本次临时对象，不能用通配符批量删除旧对象。

此演练证明数据库逻辑恢复和配套加密材料可用，**不替代正式环境的对象存储、外部身份提供商、邮件与部署切换演练**。
