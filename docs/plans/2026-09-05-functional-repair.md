## 切片顺序

1. 本地分类：分类计数按内容、新建继承当前位置、保留未分类入口、筛选结果与标题一致。验证组件交互与 SQLite 筛选。
2. 广场分类：发布保存系统分类、列表过滤、下载保留分类及模型。验证 API → 桌面与 Web 下载，历史无分类条目仍可访问。
3. 同步完整性：自定义分类、合集与成员、模型、时间戳、删除状态的往返及冲突。验证独立设备、较新者胜、保留本地。
4. 工作台与数据操作：合集成员、复制失败、导入导出、设置刷新。逐个写失败场景再修复。
5. 其余模块复审：Web、管理台、认证、启动器、更新、账单；跑对应门禁，记录实际验证边界与剩余缺口。

本轮实施顺序：先补桌面广场只读详情（加载、重试、关闭时丢弃过期响应、下载反馈），以组件交互和原生只读命令验证；随后补合集成员快照的发布、审核、下载事务，验证空合集与非法成员拒绝、成员分类模型保留及本地源不变。之后继续备份恢复与自动备份验收。

备份实施：SQLite 在线备份先写临时快照再替换目标；恢复先在临时目录迁移及校验，再用 SQLite 备份事务写入当前库，避免主文件替换与 WAL 冲突。ZIP 从同一快照导出 SQLite 与 JSON。原生后台每分钟检查开关、距上次成功 24 小时后备份；失败可见、后续重试。验证 WAL 最新提交、损坏/旧格式库、写锁失败保持原库、自动备份到期与关闭行为。

管理台实施：审核状态和上架记录在同一事务提交；同结果重试不重复上架，不同结果冲突返回 409；组件禁用进行中操作，失败保留条目并允许重试。验证并发审核、模拟上架失败回滚和无快照不误上架。

Web 实施：登录入口与退出、访客/账号内存隔离、旧账号读取响应丢弃；保存失败保留待同步副本并可重试，重新读取不覆盖待同步编辑；复制失败保留变量与预览并可重试。验证跨账号响应、失败保存重试和剪贴板拒绝，不宣称标签页数据已永久持久化。
