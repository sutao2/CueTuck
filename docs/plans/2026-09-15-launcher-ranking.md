# 启动器相关性排序与核心回归

状态：已实施验收，未部署、未发版。

## 范围与方案

只优化独立启动器的本地结果排序与核心回归入口。复用本机使用记录、收藏设置；在结果上限截取之前排序，不改变主窗口列表、广场排序或空查询收起行为，不增加联网、模型调用或数据库字段。

匹配层级为标题完全匹配、标题前缀、标题包含、其他既有命中；忽略首尾空白和英文大小写。同层级综合近期使用（30 天线性衰减，最高 30 分）、累计使用（log2(count+1)×4，最高 20 分）及本地收藏（15 分）。并列按规范化标题和 ID，避免依赖编辑时间。排序规则的测试使用固定时钟，不生成新的使用记录。

## 验收场景

- Given 正文命中已收藏且常用 When 搜索某个完整标题 Then 完整标题始终优先。
- Given 同等标题匹配 When 有近期使用、常用或收藏记录 Then 对应内容前移；旧使用记录影响逐渐减弱。
- Given 超过结果上限的候选 When 搜索 Then 先排序后截取，较早创建的精确匹配仍可回车复制。
- Given 复制失败或查询响应迟到 When 重试或继续输入 Then 不记录失败使用，旧结果不覆盖新查询。
- Given 重新唤起且收藏/使用记录已变化 When 输入同一查询 Then 重新读取并排序；本机排序不发起网络请求。
- Given 1 万条候选 When 排序 Then 单独记录 JS 排序耗时，并运行既有 SQLite 查询基准。

## 验证

新增纯函数和启动器集成回归。提供 `npm --prefix desktop run test:core`，复用登录恢复、启动器复制、翻译、公开附件、下载计数、更新与排序测试；全量 CI 仍包含这些测试，不添加重复任务。这个快速入口不替代跨平台安装、系统剪贴板和线上服务验收。本轮不部署或发版。

## 验收结果（2026-09-15）

- 核心回归入口 15 个文件、123 项通过；前端全量 100 个文件、630 项通过。
- 桌面构建、docs-check 与 diff 检查通过。
- 1 万候选 JS 排序约 7.30ms；现有原生 release SQLite 万条库查询基准约 2.00ms（命中 1 条）。两项为不同隔离测试，不代表真实端到端耗时或所有查询的延迟保证。
- 精确匹配截取前排序、回车正确复制、收藏和使用变化、无网络、时间衰减与稳定并列新增回归通过；既有复制失败不记使用、输入法和迟到响应测试保持通过。
- 未运行新的跨平台安装或物理快捷键验收；本轮不含部署和发版。
