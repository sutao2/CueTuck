# P4–P6 本地可靠性与发行准备收尾

状态：实施计划，结果按实际验证回填。不授权生产切换、真实扣费或凭据配置。

## P4 数据可靠性

1. 基于已有双库、附件哈希、墓碑与备份事务测试，新增同步 PUT 成功/GET 断网后重连、并发同步阻止、同步期间本地较新编辑保留回归。
2. 原生公共 HTTP 客户端设连接与总超时，防止发布/同步界面无限忙碌。
3. 执行 Rust SQLite 双库/备份全量、后端账号隔离全量、真实 MinIO 隔离文件往返和 PostgreSQL 隔离恢复演练；记录 1 万条真实查询耗时，不伪造性能通过。

## P5 自动回归

1. 提供 Node 单入口，逐端执行测试/构建并保存独立日志、返回失败状态；不跳过失败步骤或自动操作业务数据。
2. CI 覆盖 desktop/web/admin、backend、MCP 与文档。后端使用 CI 临时 PostgreSQL；原生测试用 macOS runner，保持 Windows 尚待实机验收。
3. 提供隔离浏览器端到端：新建、编辑、变量复制、删除取消/确认与设置返回；独立端口/内存，不依赖用户本机服务或账号。使用 Playwright；安装依赖需显式步骤，测试不连外部站点。

## P6 配置与本地打包

1. 三个前端共用服务地址解析（VITE_API_BASE）；原生三个服务入口共用 PROMPTARK_API_BASE，支持构建期值与启动环境覆盖。仅 HTTP(S) origin，不含认证/路径/查询/片段；明文只允许 loopback。
2. 固定无更新签名产物的本地调试构建命令；发行前检查 API、版本一致、更新源一致、公钥与私钥配置存在，不自动生成或替换签名材料。
3. 提供独立开发依赖 compose 与部署/备份说明模板，不触碰现有容器；明确配置、密钥和对象存储备份边界。
4. 本机联跑、打包、更新客户端与文档状态；远程 CI、签名验证、跨平台及外部提供商保持待验。

## Given / When / Then

- GIVEN PUT 已到云端而读取断网；WHEN 再次同步；THEN 内容不丢、不多出副本，保留本地较新编辑。
- GIVEN 同步未结束；WHEN 再次调用；THEN 第二次不请求远端；第一条失败后允许重试。
- GIVEN 测试失败；WHEN 运行统一验收命令；THEN 非零退出并指出对应日志；测试数据只在内存/临时库。
- GIVEN 空浏览器上下文；WHEN E2E 执行核心 CRUD/复制流程；THEN 可重复通过，不写用户 SQLite。
- GIVEN 非法服务地址或发行参数缺失；WHEN 校验/构建发行入口；THEN 明确拒绝，不悄悄发布指向 localhost 的包。
- GIVEN 无签名私钥；WHEN 本地调试打包；THEN 可构建 App，但不输出已签名更新包或宣称可发行。

## 不在本轮本地验收结论中

HTTP 投稿在“服务端已保存、响应完全丢失”时的端到端 exactly-once 保证尚无合同，不把普通队列重试称为严格幂等；生产需另行设计幂等键和保留周期。附件删除传播、孤立上传扫描、生产对象存储灾备、辅助功能授权成功路径及 Windows/Linux 实机均不冒充已验。

## P4 实测

- `syncRecovery.test.js` 3 项通过：已推送后拉取失败重试、同步防重与失败恢复、网络请求期间本地较新编辑保护。
- 后端全量 152 项通过、2 项显式环境演练默认忽略；MCP 15 项通过。SQLite 原生全量通过，含双库附件往返、备份/WAL/非法恢复回滚。
- 两个显式演练均已通过：真实 MinIO 随机合成文件上传/下载/哈希与匿名拒绝；随机 schema 到临时 PostgreSQL 数据库的恢复、凭据与正确/错误加密密钥校验。
- 恢复初跑发现 `pg_dump` 并行目录查询触发开发容器共享内存不足；仅为该子进程设置 `PGOPTIONS=-c max_parallel_workers_per_gather=0` 后通过，无全局数据库参数变更。临时 schema/库按测试清理。
- macOS arm64、Rust 1.93.0，release 模式、临时 SQLite 库 10,000 条；关键词命中 1 条实测 1.93 ms（单次本机记录，不代表跨平台或所有查询分布）。
