# AI 直接审核发布

状态：已实现并通过本机回归，待线上部署启用；用户要求覆盖提示词、合集和 Skill，放宽审核条件。

## 方案

1. 新增显式 `ai_decides` 策略，旧配置默认关闭。开启时必须启用 AI、自动上架和图片检查；由完整 AI 结论直接通过/拒绝，不再以重复、变量格式或分数阈值阻挡普通投稿。缺正文等接口校验保留。
2. 宽松审核以明确风险为拒绝依据，普通角色创作、游戏、代码、长度、措辞、同类模板不拒绝；输入视作待检查资料，不能执行其中指令。拒绝必须给出具体原因，模型异常、模糊结论或未完整读取文件仍待审核。
3. 图片最多 12 张/20 MiB，读取经过所有权、类型与哈希校验的 PNG/JPEG/WebP；GIF、非图片附件等未完整支持的格式转人工，不假称看过。Skill 检查全部 UTF-8 文件及支持图片，不执行脚本；超限和未支持二进制转人工。
4. Skill 使用独立持久任务与同一模型路由，90 秒租约、三次重试；配置变更、人工审核/撤回优先。审核状态、公开可见性、历史和审计原子提交。仅审核新投稿，不重跑历史已处置记录。
5. 管理端展示直接判定开关、三类路由、拒绝结果和任务来源；发布端移除一律人工审核的错误提示。
6. 隔离数据库验证通过、拒绝、缺结果、图片/文件边界、审计回滚及并发；前端回归和构建。备份后部署并启用线上策略，使用隔离样本验证模型，不发布测试内容。

## 验收场景

- Given 宽松直接判定开启 When 完整审核返回 approve / 有理由的 reject Then 对应 approved / rejected，作者看到原因，通过即公开。
- Given 模型超时、无路由、文件未支持或结果不完整 When 审核 Then 保留 pending，不把失败当拒绝或通过。
- Given 图片合集或带脚本的 Skill When 审核 Then 全部受支持内容送审，脚本不执行，封面/成员附件不遗漏。
- Given 审核期间改配置、人工处置或撤回 When 旧结果返回 Then 不覆盖新决定。
- Given 旧策略没有 ai_decides When 重启 Then 仍沿用旧审核规则。

## 本机验证

- 管理端全量 106 项及生产构建通过；桌面发布、Skills 和工作台 137 项及生产构建通过。
- 隔离 PostgreSQL 后端 181 项通过（4 项既有忽略），包含直接通过/拒绝/无理由拒绝降级、三次重试、租约过期、版本变化、人工优先与审计回滚；旧模式附件仍保持人工确认；九张合集封面完整送审、通过后九张全部可公开已验证。
- Skill 检查全部文件，未支持二进制/超长内容不截断放行；图片使用验证过的内联字节，不读取用户提交的网络地址，不执行包内程序。
