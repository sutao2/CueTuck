## 为什么

原 M6 仅要求待审处理、只读用户列表和一个站点开关；后续增加了 Google/GitHub 配置，但还不能支持日常运营。用户现在要求补齐管理端，不能以旧里程碑关闭或已有测试通过代替完整功能验收。

本文件是新增功能范围的唯一清单；现行规格仍用于已实现能力。特别是现行管理规格禁止用户改密/删除控件，进入相应切片前须明确修订该限制，不得绕过规格直接编码。

## 范围假设

- 面向单站点 PromptArk 运营，不扩展成多租户、通用 CMS 或服务器控制面板。
- 保留独立 `admin-web` 与本地优先边界；客户端联动仅覆盖后台规则的实际生效入口。
- 权限先使用固定角色，不做自定义角色编排器：站点所有者、运营管理员、内容审核员；普通用户不能进入管理台。角色字段、迁移与接口权限矩阵在首个切片定稿。
- 支付沿用用户要求的 mock。不能借后台管理能力发起真实扣费或伪造真实订单。
- 危险操作优先采用禁用、下架、软删除与恢复；不可逆账号清除、生产备份恢复不做无人确认的一键操作。

## 权限与数据边界

- 所有者管理管理员、登录/邮件凭据和高敏配置；运营管理员管理普通用户、内容及日常运营；审核员只查看审核所需资料并处理投稿。每项 API 按权限校验，不能只隐藏菜单。
- 本人改密要求当前密码或有效的一次性重置凭据；管理员只能发起其他人的重置流程，不能读取旧密码。对高敏角色/凭据变更要求重新验证身份。
- 初始化不能依赖公开网页“第一个注册者就是管理员”。新实例使用服务器侧一次性初始化凭据；已有实例须明确指定所有者迁移，不自动把所有普通管理员升为所有者，也不清空账号。
- 账号禁用和内容下架均记录原因；禁用不自动删除用户数据。权限改变须同步考虑数据库、Redis 缓存和已签发会话。
- 后台仅处理用户主动提交的公开内容及必要账号元数据，不提供浏览用户私有同步库、桌面 SQLite 或本机 MCP 搜索历史的入口。
- 下载统计存在用户开关和历史缺失，必须注明口径；任何导出按角色裁剪、限量并审计，不包含密钥、令牌、私有正文。
- 密钥采用现有后端加密模式；SMTP 连接目标校验、超时、速率约束与凭据输出检查须在实现前写入安全设计。

## 核心验收场景（实现时细化并映射到测试）

### Scenario: 初始化不能覆盖已有账号（A01）

- GIVEN 已初始化管理员修改了密码，或已有数据库准备升级
- WHEN 服务重启或执行升级迁移
- THEN 不覆盖原密码/角色，不重建默认管理员；重复初始化被拒绝，失败迁移可按已验证步骤恢复

### Scenario: 撤权即时生效（A01、A02）

- GIVEN 用户或管理员已持有 Access/Refresh，且权限存在缓存
- WHEN 授权操作者禁用该账号或撤销其权限
- THEN 后续受保护请求和令牌刷新被拒绝，重新登录不能绕过；并发操作不能移除最后一位有效所有者

### Scenario: 注册与重置不能越权（A03、A08）

- GIVEN 站点关闭注册或提供过期/已使用的验证令牌
- WHEN 用户通过邮箱或第三方首次注册，或重放密码重置请求
- THEN 对应操作被拒绝且不创建账号、不改变密码；错误信息不泄露邮箱是否存在

### Scenario: 审核与下架闭环（A04、A05）

- GIVEN 用户提交提示词或合集，管理员记录审核结果后又下架内容
- WHEN 作者查看发布状态、访客通过列表/详情/下载访问内容
- THEN 作者可见原因和历史，下架内容不可获取；已下载的本地副本不被远端删改

### Scenario: 分类变更没有悬空引用（A06）

- GIVEN 某大分类下存在子分类及已发布内容
- WHEN 管理员尝试删除，或明确选择迁移后删除
- THEN 默认拒绝并显示引用数量，迁移成功才删除；客户端下一次加载能使用新字典，离线本地库保持原状

### Scenario: 外部服务验收诚实（A07、A08）

- GIVEN 管理员只保存凭据，或外部提供商拒绝授权/邮件投递
- WHEN 查看配置状态及测试结果
- THEN 仅标记已配置或测试失败，不标记已验证/已送达；真实成功须有对应外部流程证据，凭据变更清除旧验证状态

### Scenario: 模拟账单不能影响真实权益（A09）

- GIVEN 使用 mock 订单、测试兑换码或模拟权益调整
- WHEN 生成、兑换、撤销或重试操作
- THEN 不触发真实支付、不改真实 Pro，重复请求不重复发放；重启行为明确遵循或先修订现行 mock 合同

### Scenario: 配置与指标真实可用（A10、A11）

- GIVEN 投稿开关关闭，统计范围包含无历史采集的日期
- WHEN 客户端直接提交投稿或运营人员查看概览
- THEN 服务端拒绝投稿；指标说明无历史数据，不能用静态数字冒充统计；保存失败保留表单并允许重试

### Scenario: 审计和交互不泄露数据（A12、A13）

- GIVEN 任一敏感写操作、导出、权限不足或会话过期
- WHEN 操作成功或失败
- THEN 结果明确且可追溯，不在日志记录秘密；无权限返回拒绝，分页/刷新/浏览器返回行为可用，不出现仅隐藏菜单的越权漏洞

### Scenario: 真实审核链路

- GIVEN 未配置模型凭据，或模拟提供商超时/返回非法结构
- WHEN 提交投稿或点击链路测试
- THEN 明确报告不可用或失败，按策略进入人工队列，不伪造模型分数、通过或通知结果
- AND 仅用户主动发布的内容可发送审核服务，本地私有库不参与；真实外部发送在明确配置后启用

### Scenario: 风控处置可追溯

- GIVEN 举报已被另一管理员处理
- WHEN 旧页面再次提交相反处置
- THEN 返回冲突且不重复下架或发送通知；原处置人与原因保留，普通用户不能读取后台私有信息

## 不在本次范围

- 真实支付接入、退款/结算、财务发票；QQ/LinuxDo 或任意新增身份提供商。
- 多租户、可视化权限编排、通用页面搭建器、独立客服工单系统。原型固定角色管理和举报处置在范围内。
- 后台读取或编辑私有本地提示词、将本机 MCP 改成公开远程服务。
- 一键执行服务器命令、无确认生产恢复、不可逆批量清除账号或对象存储。
- 代用户开通 OAuth/邮件账号、购买域名、上线生产；外部账号、域名与凭据仍由用户提供。

## 依赖与外部验收

Google/GitHub 应用、SMTP 服务及生产回调域名属于外部依赖。未提供时先用隔离服务完成自动化与失败路径验证，并明确列为“外部验收待完成”；不能将该模块或整个后台标记为全部完成。涉及邮件发送、生产部署或不可逆数据操作时，另行确认实际目标与权限。
